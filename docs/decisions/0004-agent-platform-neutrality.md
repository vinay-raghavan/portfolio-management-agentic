# 0004: Agent Platform Neutrality

## Status

Accepted.

## Context

The Kaggle capstone benefits from an ADK implementation because the competition explicitly recognizes agent systems and related Google tooling. The broader framework, however, should be reusable in Codex, Claude Code, and other agentic platforms.

The product is finance-adjacent, so policy cannot live only inside one runtime's prompt or callback implementation.

## Decision

Treat ADK as the first runtime adapter, not the architecture boundary.

The portable core consists of:

- MCP tool server.
- MCP tool schemas.
- Action-tier policy.
- Demo data contracts.
- Agentic skills and handoff prompts.
- Eval datasets and rubrics.
- Safety and refusal policy.
- Docker Compose startup flow.

Target platform paths:

- `adk`: primary capstone runtime.
- `codex`: coding-agent and implementation workflow using `AGENTS.md`, skills, MCP tools, tests, and eval commands.
- `claude_code`: coding-agent workflow using `CLAUDE.md`, MCP tools, tests, and eval commands.
- `generic_mcp_client`: direct use of the MCP policy server by any compatible client.

## Consequences

- Platform-specific adapters can differ, but behavior must remain consistent.
- MCP policy must enforce hard safety rules independently of the platform.
- The repo should include platform guidance docs instead of relying on chat history.
- Tests and evals must prove the policy boundary, not only the model response.

## Open Questions

1. Should Codex, Claude Code, and Gemini guidance files be generated by hand or from a shared source document?
2. Should platform-specific eval commands be wrappers around one common eval dataset?
3. Which platform should get the second working adapter after ADK?
